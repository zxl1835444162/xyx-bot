## 一、先确认真实用法（不是猜的）

`artifacts/storage/workspace.json` 里存着**你上次真实用的配置**：

```json
{
  "novel_path": "C:\\Users\\Administrator\\Desktop\\开局被绿，我直播捉奸震惊全网.txt",
  "book_name": "新建作品12",          "book_index": "0",
  "shortcut": "强盛集团云霄",
  "instruction": "标题字数严格限制在10到15个中文字符以内。（对话内容必须占生成
                  内容的45%以上。）（每一章的正文字数保持在2200字-2300字之间…）
                  （禁止出现任何比喻句）#@",
  "auto_accept": true, "min_words": "1", "max_words": "2300", "max_retry": "3",
  "review_model": "智慧版", "review_card": "智慧版-6A",
  "review_associate": "正常", "review_req": "强盛集团云霄拯救过稿计划",
  "review_wait": true, "review_replace": true, "review_select_all": true,
  "review_timeout": "600", "review_instruction": "", "review_chapter": ""
}
```

从这份配置能直接读出 5 个事实：

| 事实 | 含义 |
|---|---|
| 有 `novel_path`（桌面上的 txt） | 你**确实在用**「选文件 → 分章」，因为每章细纲（`#@`）来自它 |
| `instruction` 是一大段（约 250 字）约束，结尾 `#@` | **这段指令模板是你最核心的资产**，每章都靠它 |
| `min_words = "1"` | 字数下限被你设成 1 —— 说明「字数区间」这块 UI 对你是**无效的**（你的真实字数要求在指令模板里写死了 2200-2300）。这是绕过设计的信号 |
| **没有** `batch_start` / `batch_end` | 章节范围**根本没被记住** → 每次跑章都要重新手输 |
| `review_instruction`、`review_chapter` 都是空 | 「追加指令」「先打开章节」你**不用** |

再加上一个操作事实：你要跑的是 **100 章量级**的连续作业，而界面上**没有停止按钮**。

## 二、现状盘点：界面到底有哪些东西

### 侧边导航 7 项

| 页面 | 你的使用情况 | 判断 |
|---|---|---|
| 概览面板 | 不用 | **纯装饰**。内容全是"指纹级环境隔离""章节资产中台"这类宣传文案，无实际功能 |
| 星月账号 | 偶尔（登录） | 有用但**该合并** |
| 打开作品 | 不用 | 批量跑章里已自动开作品；这页是冗余入口 |
| 任务中心 | 不用 | CLI 时代遗留的"任务注册表"执行器 |
| 小说分章 | **用**（选文件/分章/指令模板/细纲） | 核心，但被埋在折叠区里 |
| 运行配置 | 极少 | 该合并 |
| 关于本机 | 不用 | 装饰 |

### 「小说分章」页内部 = 5 个折叠区 + 1 张大卡

```
★★ 批量跑章（一条龙）        ← 你唯一真正点的按钮
▸ 流程准备（登录/保存 cookie）  ← 与「星月账号」页重复
▸ 选文件 / 分章 / 工程         ← 需要
▸ 指令模板（#@ = 当前章）      ← 需要，但编辑框只有 3 行高（你那段有 250 字！）
▸ 章节列表（填每章细纲）        ← 需要（分章后自动）
▸ 单章续写/审稿（高级参数）     ← 你**不用**，却占了半屏：
     · 作品名称 / 第几本 / 续写到第几章（下拉）
     · 快捷选项 + 「填入默认」
     · 字数自动采纳（勾选 + 下限/上限/重试）
     · AI 审稿参数（模型/卡片/联想/审稿要求/追加指令/先打开章节/3 个开关/超时）
     · 「一键续写」「AI 审稿」「续写+审稿 一条龙」三个按钮
```

### 由此暴露的真实缺陷（不只是"多"，还有"错"）

| # | 缺陷 | 证据 / 后果 |
|---|---|---|
| 1 | **切页会丢未保存的编辑** | `show_page` 会 `destroy()` 整页所有控件，回来时从 `workspace.json` 回填 → 你在指令模板里改的字、填的范围，**没点保存就切页就没了** |
| 2 | **跑到一半切页会报错** | 运行的 worker 会 `self.after(0, ..., self._btn_ai_batch.set_text)`，而那个按钮已被销毁 |
| 3 | **没有停止按钮** | 100 章的作业只能关窗口 |
| 4 | **逐章进度回调是死代码** | `ai_flow.py` 里定义了 `_progress(no)`，但调 `ai_batch_chapters` 时**根本没传进去** → 按钮上的"执行中 N/M"和"—— 第 N/M 章 ——"从来不出现 |
| 5 | **章节范围不持久化** | 见上 |
| 6 | **指令模板编辑框只有 3 行高** | 你那段 250 字的模板，在一个 3 行的小框里编辑 |
| 7 | 字数区间语义混乱 | 你只能靠 `min=1` 绕开；UI 没有解释"1 = 不校验" |
| 8 | 「流程准备」在两处重复 | content.py 与 account.py 各一套 |

## 三、新的信息架构

### 导航从 7 项 → 3 项


### 三个关键交互原则

1. **一页走完**：作品 → 范围 → 指令 → 参数 → 开始，全部在同一列、从上到下，不再需要跨页拼配置。
2. **状态可见**：登录态、站点现有章节、缺章数、当前进度、每章耗时与结果，全部显式呈现。不让你"猜它现在在干嘛"。
3. **可中断**：任何时刻都能点「停止」，协作式取消会在一个轮询周期内生效。

## 六、验收标准

1. 打开程序默认落在「跑章」页，一屏内能看到：状态条 / 作品 / 范围 / 指令模板 / 开始按钮。
2. 从「跑章」页能完成一次完整配置 + 预检，**不需要切换任何其他页面**（除非要登录或重新分章）。
3. 点「停止」能在数秒内停下，并保留已完成章的记录。
4. 跑完后逐章结果表列出每章的 ✓/✗、字数、耗时；能一键"从失败章重跑"。
5. 切页不再丢编辑、不再因为控件被销毁而报错。
6. 全部测试通过（含新增的预检/ETA/中止测试）。

| 发现 | 说明 |

## 八、第二轮（2026-10-04 续）：把"操作分散"再往前推一步

第一轮解决了**导航分散**（7 页 → 3 页）。第二轮继续处理**操作过程中的分散**：
"我该干什么？跑到哪了？结果在哪？"这三件事原来都得自己记。

| # | 新功能 | 解决的问题 |
|---|---|---|
| 1 | **「还差这几项」待办条** | 打开界面直接告诉你缺什么（登录态 / 细纲 / 作品名 / 范围），每项配一个按钮把你送到该去的地方。不用满界面找、也不用记流程 |
| 2 | **「接着上次继续」** | 连载场景（今天 3~10、明天 11~20）一键设好下一段，**沿用上次的段长**。跑完自动记住"成功跑完的最高章" |
| 3 | **「拉结束章到最新」** | 预检后知道站点共 N 章，一键把结束章设成 N |
| 4 | **结果导出 CSV** | UTF-8-BOM，Excel 打开不乱码；列：章号 / 结果 / 字数 / 耗时秒 / 原因 |
| 5 | **复制失败章号** | 一行 `5,7,9` 进剪贴板，方便贴到别处 |

### 第二轮顺带修掉的坑

| 坑 | 说明 |
|---|---|
| **占位符看起来像真值** | 跑章范围的占位符原来是裸数字 `3` / `10`，界面上**和真填了一模一样** → 用户以为已设好，点「开始跑章」却被告知"没填范围"。改成 `如 3` / `如 10`（截图验收时发现的） |

| 待办文案里混进了 Markdown | 第一版在 `tk.Label` 里写了 `**空的**`，星号会原样显示。已改成纯文本 |
| **测试会覆盖用户真实配置** | `test_gui_pages` / `test_runplan` 现在都把 `workspace.WS_FILE` 指向临时目录 —— `artifacts/storage/workspace.json` 里是用户真实的跑章配置（小说路径 / 作品名 / 那段 250 字指令模板），测试绝不能写它 |
