目标站点：[星月写作](https://xingyuexiezuo.com/)。

> [`MACOS_PORT.md`](MACOS_PORT.md)。

架构**移植自** `novel-publisher-mac`（同作者的网文发布工具），复用了它经过实战的：
浏览器引擎（CDP 接管 / 反自动化检测）、跨平台浏览器检测、**平台注册表**、**任务注册表**、
章节文件工具、日志重定向。

## 三、星月写作免登录（登录一次，长期复用）

这是本项目的核心便利功能：**只需登录一次，之后每次自动复用会话。**

### 怎么用

主界面左侧 →「**星月账号**」页：

| 按钮 | 作用 |
|---|---|
| **登录星月账号** | 弹出浏览器，你扫码或输账号密码；**不限时**，登录好为止 |
| **我已登录，立即保存** | ★ 不依赖自动检测 —— 你确认登录成功了就点它，强制保存会话 |
| **校验登录态** | 打开站点确认会话现在还有效，并顺手刷新快照 |
| **清除登录态** | 登出（需二次确认），下次需重新登录 |

**推荐流程**（最省心）：

1. 点「**登录星月账号**」→ 自动用本机 Edge 打开星月写作登录页
2. 你在浏览器里扫码 / 输账号密码（有腾讯滑块也能手动过）
3. 看到自己已经登录进去了 → 回软件点「**我已登录，立即保存**」
4. 提示「登录态已保存 ✓」，关掉浏览器即可

> **不用等程序自己判断。** 如果自动检测没反应过来（选择器变了、页面结构变了，
> 或者你登录后跳到了别的标签页），点「我已登录，立即保存」一样能存下来。
> 还可以保持浏览器开着，随时点、随时存。

超过 **5 分钟**没登录完也不会失败 —— 程序会一直等，直到你确认或手动关闭。

之后每次跑任务，`ensure_login` 一进站点就发现已登录，**零交互直接开工**。

### 原理

星月写作把登录态存在 cookie + localStorage。本项目用 Playwright 的
`storage_state` 把这两样一次性导出成 `artifacts/storage/state.json`；
下次启动浏览器时把它注入 `new_context(storage_state=...)`，
结果等同于「你已经登录过了」。

```
第一次： 打开浏览器 → 未登录 → 你登录 → 点「我已登录，立即保存」→ state.json
第 N 次： 打开浏览器 → 注入 state.json → 已登录 → 直接干活
```

登录判定采用**多路校验**，避免"明明登录了却判不出来"：

1. 先排除「页面还在登录页」的情况（登录 Tab / 二维码 / 输入框可见）
2. 查 `localStorage` 里有没有 token / userInfo 之类的票据 ← SPA 最可靠
3. 查页面上有没有「我的作品」「退出登录」等已登录标志
4. 兜底：已经离开登录页，就认为已登录

相关代码：
- `src/session.py` — state 的保存 / 读取 / 摘要 / 清除，以及元信息记录
- `src/login.py` — `ensure_login`（复用优先）、`save_session`（成功后落盘）、
  `verify_session`（校验）、`manual_login`（支持手动确认）、`login_state_report`（诊断）
- `src/browser.py` — `resolve_auth_file` 自动找 state 并注入

### 没记录到？跑诊断

```bat
.venv312\Scripts\python.exe main.py diag
```

会打开浏览器并打印：URL、**全部 cookie**、localStorage 内容、判定结果、命中的标志元素。
一眼就能看出是"真的没登录"还是"登录了但没存下来"。

### 细节

- 保存时会**先备份**旧 state 到 `state.backup.json`，防止写坏没得退。
- `session_meta.json` 记录保存时间、cookie 条数、猜到的账号，界面直接读它。
- 登录流程**不限时**，不会因为超时把已经登录好的会话丢掉。
- 会话过期（站点主动失效 / 太久没用）时，会打印「已失效，需要重新登录」，再点一次登录即可。
- 登录态是**明文 JSON**，里面是你的登录票据 —— **别外传、别提交到 git**（`.gitignore` 已排除 `artifacts/`）。
- 想彻底清掉：按「清除登录态」，或直接删 `artifacts/storage/state.json`。

- **改版后切页不再丢编辑**：页面改成「构建一次、只显示/隐藏」，

### 作品页的两个大坑（都踩过，已解决）

**坑 1：「新建作品」不是唯一文字**

页面上同时存在：

| 元素 | 特征 | 能否点 |
|---|---|---|
| 新建作品**入口卡** | class 含 `create-card` | ✅ 这才是目标 |
| 已有作品 A | 名字恰好叫「新建作品」 | ❌ 别碰 |
| 已有作品 B | 名字叫「新建作品1」 | ❌ 别碰 |

用 `text=新建作品` 会**命中 4 个**，必然点错。
正确做法是用 class 精确锁定：

```python
create_card = ".create-card"                        # ✓ 唯一
existing    = ".book-card:not(.create-card)"        # 已有作品卡
```

**坑 2：作品名会重复**

实测出现过 **3 部同名「自动化测试-勿动」**。所以「打开某个作品」绝不能只靠名字。

真正的唯一标识是卡片内的链接：`#/chapters/<数字ID>`

```python
from src import books as B
B.list_books(page)
# → [{"title":"xx", "book_id":"2368291", "words":"0字", ...}, ...]

B.match_books(books, "自动化测试")     # 模糊匹配，返回全部命中
B.open_book(page, "新建作品1")          # 唯一命中 → 直接打开
B.open_book(page, "自动化测试", index=2)  # 命中 3 个 → 选第 3 个
B.open_book(page, "自动化测试")          # 命中多个又不给 index → 拒绝执行（安全兜底）
```

**坑 3：活动弹窗盖满页面**

进作品页会自动弹「邀请好友赚佣金大奖赛」，里面是个 `n-data-table` 排行榜，
**整个弹窗覆盖全屏**，导致后续所有点击报
`intercepts pointer events` 而失败。

`close_activity_modal()` 会自动识别并关闭它（用标题文字识别，
绝不会误关「新建作品」弹窗），`goto_books` / `open_book` / `click_create_book`
里都会先调一次。

## 六、浏览器：默认用本机 Edge

**自动检测并优先使用本机 Edge**，理由：

1. **不用下载 Chromium 内核**（Playwright 自带内核 ~150MB）
2. **指纹更真实** —— 真实 Edge 的 `navigator`、插件、字体都自然，风控更宽松

已实测：`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` 启动成功。

优先级：`config.BROWSER_PATH` 显式指定 > 自动检测 Edge/Chrome > 回退内置 Chromium。

## 八、命令行用法

| 命令 | 作用 |
|---|---|
| `prepare` | ★ 流程准备：打开网站 → 检测/登录 → 保存 cookie 与缓存 |
| `login` | 登录一次并保存登录态（之后免登录，不限时） |
| `session` | 查看登录态详情（时间 / cookie 数 / 路径） |
| `check` | 打开站点校验登录态是否有效 |
| `diag` | ★ 诊断登录态（排查「为什么没记录到 cookie」） |
| `recon` | 侦察页面，打印可见元素 |
| `books` | ★ 列出作品页所有作品（带 ID / 字数 / 创建时间） |
| `open <名字>` | ★ 按名字打开指定作品，同名加 `--index N` |
| `ai <作品名>` | ★ AI 续写正文（细腻版 + 联想正常 + 最近10章） |
| `review <作品名>` | ★ AI 审稿（智慧版-6A + 联想正常 + 指定审稿要求） |
| `auto <作品名>` | ★★ 一条龙：续写 → 采纳 → 关弹窗 → 等正文 → 审稿 → 替换 |
| `batch <作品名>` | ★★ 批量跑章：第 --from ~ --to 章逐章一条龙（自动切章/新建） |
| `studio` | 登录并进创作台 |
| `tasks` | 列出所有已注册任务 |
| `platforms` | 列出所有已注册平台 |
| `run <任务名>` | 执行指定任务 |
| `browsers` | 检测本机可用浏览器 |
| `logout` | 清除登录态 |

```bat
:: 首次：登录一次（弹出浏览器，扫码或输密码）
.venv\Scripts\python.exe main.py login

:: 看看登录态存得怎么样
.venv\Scripts\python.exe main.py session

:: 以后直接用，不会再要求登录
.venv\Scripts\python.exe main.py studio

:: 看看都有哪些作品（带 ID，用于确认定位依据）
.venv\Scripts\python.exe main.py books

:: 打开某个作品（名字唯一时）
.venv\Scripts\python.exe main.py open 新建作品1

:: 名字重复时：指定第几个（从 0 开始）
.venv\Scripts\python.exe main.py open 自动化测试 --index 2

:: 或者用 ID 打开，绝对精确
.venv\Scripts\python.exe main.py open 2368259
```

`open` 不带 `--index` 时，如果命中多个同名作品，会在终端列出候选让你输入序号。

### ★ 短代号怎么用（核心）

分章后，每一章都得到一个**短代号**：`#1` `#2` `#3` …

代号代表**你在那一章输入框里填的细纲**。然后你在「指令模板」里写一段自然语言，
把代号嵌进去就行：

```
根据 #1 的细纲，续写下一段正文，保持爽文节奏。前文脉络参考 #2。
```

程序会把 `#1` 替换成第 1 章你填的细纲、`#2` 替换成第 2 章的，得到最终送进站点的文本。

兼容写法（都认）：

```
#1        #1        [1]        {{第1章}}        第1章
```

**几个细节：**

- 不存在的代号（比如 `#999`）**原样保留**，方便你发现写错了
- 写了代号但那一章**还没填细纲** → 会有 ⚠ 提示，用原文兜底
- 指令模板里可以**出现多个代号**，也可以代号和普通文字混着写
- 想给每章内容套统一前后缀？勾选「给每章内容套统一前缀 / 后缀」

### ★ 按字数自动采纳 / 重新生成

生成完之后，AI 续写弹窗底部会出现一排按钮：

```
上一步 | 重新生成 | 继续追问 | 复制 | 对比 | 导出至作品 | 推送至备忘录 | 采纳使用
```

右下角有个数字（如 `1990`）就是**本次生成的字数**。可以定个区间，
让程序自己判断：

| 情况 | 动作 |
|---|---|
| 字数 **在** `min ~ max` 之间 | 点「**采纳使用**」 |
| 字数 **不够** 或 **超了** | 点「**重新生成**」→ 等新一轮 → **回到同一判断** |
| 重试用完仍未达标 | 取回当轮（尽力而为），**不空转** |

> ★ 关键：点「重新生成」之后**不是直接结束**，而是**回到字数判断**，
> 一轮一轮来，直到符合区间（或重试用完）。

**界面用法：** 分章页 → 「生成字数（自动采纳）」→ 勾上开关，填区间
（默认 `2100 ~ 2300`）+ 重试次数（默认 `5`）。

**命令行：**

```bash
python main.py ai 新建作品1 --template "#1" --project demo.novel.json --go \
    --auto-accept --min-words 2100 --max-words 2300 --max-retry 5
```

| 参数 | 说明 |
|---|---|
| `--auto-accept` | 开启自动采纳（不加则不判断） |
| `--min-words 2100` | 字数下限 |
| `--max-words 2300` | 字数上限 |
| `--max-retry 5` | 最多重新生成几次 |

**环境变量（任务中心用）：** `XY_AUTO_ACCEPT=1`、`XY_MIN_WORDS`、
`XY_MAX_WORDS`、`XY_MAX_RETRY`。

> ★ **有个现实问题**：如果提示词本身写得短，生成的字数会长期偏低
> （实测某个提示词只有 1600~1800），那它就**一直在重生成路径上转**。
> 所以代码里留了两层保底：
> - `hard_min`：硬下限，重试用完时若 ≥ 它仍然采纳
> - `best_effort`：重试用完仍未入区间 → 采纳最后一轮
>
> 想严格不放水就把 `best_effort` 关掉。

#### ★ 怎么知道「生成完了」？（这个坑很关键）

一开始想用「字数不再变化」判断，**结果是错的**：生成途中会停顿，
一停顿就被误判成「完成」，读到的是**上一轮的旧字数**，看起来像
「重新生成没生效」。

逐 3 秒采样整个生成过程后，得到**可靠判据**：

| 状态 | 弹窗按钮栏 |
|---|---|
| **生成中** | `[提示词] [""] [停止生成]`（正文 textarea 字符数持续增长） |
| **已完成** | `[上一步] [重新生成] … [采纳使用]` |

即：**「重新生成」按钮出现 = 生成完成**；**「停止生成」按钮在 = 生成中**。
代码里就是 `gen_finished()` / `gen_in_progress()`。

点完「重新生成」还要**等旧结果页下架**（`wait_result_gone()`），
否则下一轮 `wait_generation` 会立刻把旧页面当新结果。

### ★ 站点交互的三个坑（都实测过，已解决）

写这套自动化时踩的坑，记下来免得重踩：

**1. 模型面板是「两级」的，点分类不等于选中**

面板左边是**分类**（智慧版/细腻版/…），右边是该分类下的**模型卡片**。
只点左边的「细腻版」→ 只是高亮切换，顶部仍显示「奇想版」。
必须再点**右栏卡片里的「选择」**，最后点「**使用此模型**」才生效。

>> 代码里 `select_model()` 会在最后**回读顶部选择器**做断言，不是「点了就报成功」。

**2. 「联想能力」是滑块，不是开关**

模型面板左下角「联想能力」按钮，点开是个浮层滑块：

```
专业 · 0.1 | 准确 · 0.2 | 均衡 · 0.5 | 正常 · 0.7 | 丰富 · 1.0 | 离谱 · 1.1
```

**点轨道没用，必须拖手柄**，拖到对应刻度 x 会自动吸附。
`set_associate_level()` 按刻度标签的 x 坐标拖拽。

**3. 「关联章节」整行是个折叠开关，别点！**

「关联章节」那一行**点了会折叠成「已保留，不引用」**，整个板块失效。
它是默认展开的，**不要点它**。

真正的操作是：滚到按钮组 → 点「最近N章」右边那个 **`⌄` 箭头（svg）**
→ 弹出菜单 `最近5章 / 最近8章 / 最近10章` → 点「最近10章」。

### 剧情文本的四种来源（命令行）

1. `--plot "..."` 直接给一段（优先级最高）
2. `--template "根据 #1 续写"` + `--project xx.novel.json` → 短代号替换 ★推荐
3. `--project xx.novel.json --chapter 3` → 取该章单章（含前后缀）
4. 都不给 → 用内置的默认占位剧情

## 八点六、★ AI 审稿（与「AI续写正文」同级）

工具栏上「AI审稿」和「AI续写正文」是**并排的同级按钮**，但**界面形态完全不同**——
这是本项目最容易踩坑的地方：

|  | AI 续写正文 | **AI 审稿** |
|---|---|---|
| 承载 | 居中**弹窗** `.n-modal` | **右侧抽屉**（`n-split-pane` 内） |
| 面板锚点 | `.n-modal:has-text(...)` | `.n-card-content:has-text('待审文本')` |
| 主要输入 | 「后续剧情」textarea | **待审文本** textarea |
| 提示词 | 「续写要求」下拉 | **审稿要求**（3 个 tab） |
| 开始按钮 | 「开始 AI 续写」 | **「生成」** |
| 结果落盘 | 「采纳使用」 | **「替换 / 插入」** |

> ★★ 因为审稿走的是**抽屉**（不是弹窗），
> **`.n-modal` / `[role=dialog]` 全都抓不到它**！
> 并且面板容器类 `chapter-side-pane-c` 是**动态生成的、不可靠**，
> 所以一律用**文字锚点**：`.n-card-content:has-text('待审文本')`。

### 你要的配置（用户指定，已做成默认）

- **模型**：智慧版 → **智慧版-6A**（★ 注意：分类名 ≠ 卡片名）
- **联想能力**：**正常 = 0.7**
- **审稿要求**：快捷选项里那句 `强盛集团云霄拯救过稿计划（智慧5.6内测专属，审稿前10章）`

### 完整链路（重要）

```
★ 先打开一个章节（不打开的话正文区是空的 → 待审文本也是空的）
   → 点「AI审稿」→ 打开抽屉
   → 选模型（智慧版 → 智慧版-6A）+ 联想能力 正常(0.7)
   → 待审文本（默认自带当前章正文；填了「追加指令」→ 提示词 + 正文拼接）
   → 审稿要求：切「快捷选项」tab → 选目标提示词
   → 点「生成」（★ 卡片右下角的「生成」）
   → ★ 等生成完成（几分钟很正常，最多等 600s）
   → ★★ 先「全选正文」→ 再点「替换 / 插入」落盘到正文
```

> 用户原话：「生成完，需要点击**替换**，点击之后，ai审稿的**生成结果**就替换进去了。」
> 所以 `wait_done=True` + `replace=True` + `select_all=True` 是**完整流程的标准用法**。

### ★★ 两个必须遵守的动作（用户 2026-10-03 明确要求）

**① 替换前必须「全选正文」**

「替换 / 插入」是**智能双模**，同一个按钮两种行为（鼠标悬浮提示实测）：

| 当前状态 | 按钮行为 |
|---|---|
| **有选中文本** | **替换** — 用生成结果替换选中内容 |
| **没有选中文本** | **插入** — 在光标处插入，**原文还在** |

不全选就直接点，结果是「**原稿 + 审稿结果**」**前后拼接**在一起：

```
sadasdadsd啊可是觉得就看见拉萨<s>…</s>请提供需要审改的本章正文。…   ← ✗ 拼接
```

所以流程固定为：**生成完成 → `select_all_body()` → 点「替换 / 插入」**。

全选两条路（实测都能选中全文）：

```python
# ① 首选：工具栏「全选」按钮 —— ★ 属性是 aria-label，不是 title！
page.locator("button[aria-label='全选']").first.click()
# ② 兜底：编辑器聚焦 + Ctrl+A
page.evaluate("() => document.querySelector('.tiptap.ProseMirror').focus()")
page.keyboard.press("Control+a")
```

> ★ 编辑器正文 = `.tiptap.ProseMirror`（contenteditable）。
> 工具栏按钮**全部用 `aria-label`**：撤回 / 撤销撤回 / 复制 / **全选** / 搜索 /
> **替换**（★ 这是编辑器查找替换，跟审稿的「替换 / 插入」**不是一回事**）/ 词条库 /
> 角色库 / 高频词透镜 / 统一中文标点 / 智能排版。
> 所以**绝不能用全页文字匹配「替换」**——两处都有「替换」。

**② 待审文本 = 自带章节正文 + 可追加提示词（支持多行）**

打开审稿面板时，**「待审文本」已经自动填好了当前章正文**（不用我们填）。
但用户希望在这基础上**再补一些提示词**（原话：「我除了正文还需要添加一些提示词」），于是：

```
（提示词） 请按爽文节奏审改以下正文，重点检查毒点与逻辑断裂。
          不要新增剧情，不要改变原有情节走向。
          严格保留人物设定与说话风格。

————————以下为待审正文————————

（正文） 　　sadasdadsd啊可是觉得就看见拉萨…
```

> ★ 界面上「追加指令」是**多行编辑器**（不是单行框），可以写多条要求，一行一条。
> 旁边有 4 个快捷按钮一键插入常用提示词：
> **爽文节奏 / 只改不通顺 / 多删少改 / 保留人设**，还有「清空」。
> 点快捷按钮是**追加**（不会覆盖已写的内容），方便叠加多条。

三个分支（`fill_review_text`）：

| `text` | `instruction` | 行为 |
|---|---|---|
| 非空 | — | 用 `text` **完全覆盖**（优先级最高） |
| 空 | 非空 | **提示词 + 分隔线 + 当前章正文** 拼成一段填入 |
| 空 | 空 | **不动**，沿用页面自带的当前章正文 |

> ★ 拼接用的正文是**实时从编辑器读的**（`get_body_text()`），
> 所以换章节后再审，拼进去的就是新章节的内容。
> 提示词里的 `\n` 会**原样保留**，送进去就是多行文本。

### 界面用法

「小说分章」页 → **一键 AI 续写** 卡 → 往下滚到「**AI 审稿参数**」：

```
             ┌────────────────────────────────────────┐
```


### ★ 审稿专有的三个坑（都实测过）

**1. 模型选择弹窗是「根级」的，跟抽屉平级**

点审稿抽屉里的「AI模型」下拉，弹出的`模型选择面板`**挂在 `<body>` 下**
（`.n-modal.model-picker-modal`），**不在抽屉内部**。
所以代码里 `select_model(container=抽屉, read_container=".n-modal")` 两个容器**要分开传**：
去抽屉里「点开」，但面板本体/回读在 `.n-modal`。

> 早期把 `container` 直接传成抽屉 → `{抽屉} button:has-text('智慧版')`
> 找不到分类，模型一直选不上。

**2. 「生成」按钮不在 `.n-card-content` 里**

DOM 实测：`生成` 在 `.n-card__footer`（卡片底部**固定栏**），
而 `.n-card-content` 只是中间那个可滚动内容区。所以锚点要用**整个卡片**：

```css
.chapter-right-workspace .n-card.chapter-side-pane-c
```

> 顺带一个坑：**不能用全局 `button:has-text('生成')`** —— 会命中
> 左栏章节菜单浮层里的「一键生成概要」，`.first` 直接点错。

**3. 生成完成后，「待审文本」标签会消失**

为了显示结果，卡片内容区被换成结果视图，
`chapter-side-pane-card` 这个类也会掉，只剩 `chapter-side-pane-c`。
→ 所以**结果判据不能靠「待审文本」**，要靠 **footer 里的
`button.n-button--success-type`**（就是那个绿色的「替换 / 插入」）。

> 更严重的一个坑：**别用「全页文字含『替换』」判断完成**。
> 页面上别处也可能有这两个字，会导致刚点完生成就误判
> 「已完成（耗时 0s）」，然后点替换必然失败。
> 正确做法：**限定在卡片 footer 内 + 限定 success 类名**，
> 并且**连续 2 次命中**才算数。

**4. 审稿前必须先把章节「点开」，但 `editor_ready()` 会骗你**

进作品编辑器后**不一定会自动打开章节**，此时正文区是空的，待审文本也是空的。
坑在于：`.tiptap.ProseMirror` **一直存在**（空壳），所以

```python
# ✗ 只判存在 → 空壳也返回 True，误以为「已就绪」
AI.editor_ready(page)

# ✓ 要求正文非空 → 才知道要不要去点章节
AI.editor_ready(page, need_text=True)
```

另外两个连带坑：

- **「是否默认打开上次章节？」是居中模态，会截获所有点击** →
  直接点章节会 `Locator.click: Timeout 4000ms exceeded`。
  `open_chapter()` 里**第一步就先 `dismiss_dialogs()`**。
- 点**容器** `.chapter-item`（宽 274px），**不要点标题** `h3.chapter-item__title`
  （只有 36px 宽，容易点偏）。容器里还有个「生成」按钮，别点到它。

左栏章节 DOM 实测：

```html
<div class="chapter-item chapter-item--active ...">   <!-- ★ 点这个 -->
  <h3 class="chapter-item__title">第2章</h3>
  <span class="chapter-item__meta">104 字</span>
  <div class="chapter-item__hover-actions">… 生成</div>  <!-- 别点 -->
</div>
```

### ★ 关于弹窗处理（统一原则）

用户明确要求：**所有关弹窗逻辑「有则关、没有就跳过」，绝不影响主进程。**

代码里体现在：

- `open_review_pane()`：每轮先 `dismiss_dialogs()`，重试 4 次，全程
  `try/except` 不抛异常；
- `replace_review_result()` → `dismiss_review_confirm()`：
  替换后的二次确认框**有则点确认、没有直接跳过**，返回点掉的数量（0 也正常返回）；
- 各种 `dismiss_*` 一律返回计数，**不做「必须关掉才算成功」的假设**。

## 八点七、★★ 一条龙：续写 → 审稿（最易崩的衔接处）

用户担心的是这个：
> 「一章的生成已经完成了，我有些担心**生成完之后、与审稿开始之间的状态**。」

**这个担心完全正确**，实测截图证实了：生成完之后，**续写弹窗还开着**
（右下角有绿色的「采纳使用」），而它是**居中模态**，
把后面「AI审稿」按钮的点击**全部拦掉** →
`Locator.click: Timeout 4000ms exceeded`×4 → 审稿打不开。

### 衔接处的三个坑（都实测过）

| # | 坑 | 现象 | 解法 |
|---|---|---|---|
| 1 | **采纳后续写弹窗不自动关** | 模态拦截，点「AI审稿」必超时 | `close_continue_dialog()` 主动关 |
| 2 | **正文写入有延迟** | 立刻审稿会读到空/旧正文 | `wait_body_change()` 等字数真的变了 |
| 3 | **超上限被判失败 → 不采纳** | 弹窗留着不走，后续全崩 | `best_effort` 修正为「多了也认」 |
| 4 | **★ 续写/审稿是两套提示词库** | 用同一个关键词 → 空选 或 选错 | 分别用各自关键词（见下节） |
| 5 | **★ 快捷选项面板异步加载** | 打开瞬间 0 项 → 误判「没这条」 | `wait_shortcut_loaded()` 等列表渲染 |

### ★★ 坑 4：续写 / 审稿是【两套完全不同的提示词库】

**这是最容易踩的坑**——两边的「快捷选项」面板长得一模一样，但**内容不通用**：

| 位置 | 提示词全名（实测） |
|---|---|
| **续写**「快捷选项」 | `强盛集团云霄最强续写逆徒尊享版（细腻优先，奇想其次）` |
| **审稿**「审稿要求 → 快捷选项」 | `强盛集团云霄拯救过稿计划（智慧5.6内测专属，审稿前10章）` |

所以：

* **续写**传 `shortcut="强盛集团云霄最强续写"`
* **审稿**传 `review_req="强盛集团云霄拯救过稿计划"`
* 两边**不要混用**——若用同一个串，续写面板里匹配不到（0 项）

界面默认值已分别设好：`DEFAULT_SHORTCUT`（续写）与审稿要求关键词各管一边。

### ★★ 坑 5：快捷选项面板是【异步加载】的

打开面板的**那一瞬间是 0 项**，页面显示
「已收藏 0」「**正在加载收藏提示词…**」，要等 **2~6 秒**
才渲染出 27~30 条。不等就直接 `count()` → 拿到 0 →
误判「面板里没有含该关键词的提示词」→ **明明有却选不上**。

解法：打开面板后**必须**先调 `wait_shortcut_loaded(page)`：

```python
def wait_shortcut_loaded(page, timeout=20.0, poll=1.5) -> int:
    """轮询 .shortcut-picker-modal .prompt-row 计数，
       看它是否 > 0 且连续两次稳定，稳定后返回项数。"""
```

实测日志：

```
[ai] ✓ 快捷选项面板已打开
[ai]   快捷选项面板已加载 27 项…
[ai] ✓ 快捷选项加载完成（27 项）
[ai] 命中（has-text('强盛集团云霄最强续写')）：
      '强盛集团云霄最强续写逆徒尊享版（细腻优先，奇想其次）'
```

另外：`pick_shortcut()` 里「**有关键词但没命中**」现在是
**温和跳过**（打警告 + 截图，但**不阻断主流程**），
符合「有则改、没有就跳过、不影响进程」的要求。

### 终局收尾：`close_review_pane()`

一条龙跑完（审稿 → 替换）时，**右侧审稿抽屉是开着的**。
它会盖住右半边，导致后续读正文/点别的元素拿到错对象
（实测：E2E 结论段读到 216 字就是这个原因）。
所以 `ai_auto_chapter()` 在替换成功后会**自动关掉审稿抽屉**：

```python
def close_review_pane(page, wait=1.0, max_try=3) -> bool:
    """关右侧「AI审稿」抽屉；有则关、没则跳过，不抛异常。
       策略：抽屉关闭按钮 → ESC → 点遮罩。"""
```

单独用的判断/关闭：

```python
AI.review_pane_open(page)     # 审稿抽屉是否开着
AI.close_review_pane(page)    # 关掉它
```


**坑 1 的关闭按钮**（实测 DOM）：

```html
<button aria-label="close"
        class="n-base-close n-base-close--absolute n-card-header__close">
</button>   <!-- 弹窗右上角，约 18x18 -->
```

`close_continue_dialog()` 按 **关闭按钮 → ESC → 点遮罩** 顺序试，
**有则关、没则跳过**，全程不抛异常。

**坑 3 的修正**（`generate_with_word_check`）：
原来 `best_effort` 只在「字数**不够**」时兜底，
**超过上限直接判失败**（`3524 字超过，重试 0 次仍未达标`）→ 不点采纳 → 弹窗留着。
现在改成**「多了也认」**：

```python
# 只要 cnt > 0，超上限也尽力采纳（避免弹窗挂着不走）
if best_effort and cnt > 0:
    print(f"⚠ {cnt} 字{why}，重试用完 → 取回本轮（尽力而为）"
          f"{'（超过上限，也认）' if cnt > max_words else ''}")
    return _accept_now(cnt, "尽力而为")
```

## 八点八、★★ 流程准备（所有流程开始之前）

用户需求（2026-10-03）：

> 「在所有的流程开始之前，有一个打开网站提前配置，然后进行 cookie
>   或者缓存保存的功能，然后之后点击一条龙服务，就直接开始。」

### 为什么需要这一步

星月写作的登录态（cookie + localStorage）**不保存的话每次都要重登**。
「流程准备」就是把「打开网站 → 登录/配置 → 保存会话」做成**一步**，
跑一次之后长期免登录，之后点「一条龙」直接开跑。

### 它做了什么（`login.prepare_session()`）

| 步骤 | 说明 |
|---|---|
| ① 打开网站 | 自动注入已保存的登录态 → **多数情况直接就是「已登录」** |
| ② 检测登录态 | cookie + localStorage 双路判定 |
| ③ 登录（如需要） | 环境变量账号密码自动登录 → 再不行 → 人工扫码（不限时） |
| ④ ★ **保存 cookie + 缓存** | 导出到 `artifacts/storage/state.json`（下次免登录） |
| ⑤ 返回摘要 | `{ok, logged_in, saved, cookies, account, saved_at, mode, message}` |

`mode` 取值：`reuse`（复用已有）/ `auto`（自动登录）/ `manual`（人工）/ `failed`。

### 界面用法（「小说分章」页最上方）

「小说分章」页顶部有 **① 流程准备** 卡片：

```
● 已有登录态（2026-10-03 23:06:26 · 4 条 cookie）（刚刚）
[① 打开网站并保存] [我已登录，立即保存] [刷新状态] [清除]
[② 一条龙：续写 + 审稿]   准备 → 打开作品 → 开章节 → 续写 → 采纳 → 审稿 → 替换
```

* **① 打开网站并保存** —— 打开浏览器，检测/登录，保存 cookie 与缓存
  （后台线程跑，不卡界面；要登录时你在浏览器里操作）
* **我已登录，立即保存** —— 万一程序没自动检测到，点它强制导出（以你看到的为准）
* **刷新状态** —— 只查本地登录态文件，不开浏览器
* **清除** —— 登出（删 state.json），二次确认
* **② 一条龙** —— ★ 直接开跑；若本地**没有**登录态，会**先提醒你去做准备**

### 命令行用法

```bash
python main.py prepare              # 打开网站 → 检测/登录 → 保存
python main.py prepare --no-open    # 不开网站，只做本地状态检查
python main.py prepare --clear      # 清除登录态（登出）
```

实测输出（登录态有效时）：

```
[prepare] 已有登录态：2026-10-03 19:41:36 · 4 条 cookie
[session] ✓ 登录态已保存（4 条 cookie）
[prepare] ✓ 准备就绪 · 已保存 cookie 与缓存，可直接点「一条龙」（mode=reuse, cookies=4）
```

### 一条龙会自动准备

`main.py auto` 与 UI 的一条龙，**默认都会先检查准备状态**：

* 已有登录态 → 跳过准备（日志提示「已有登录态，跳过准备」）
* 没有 → 自动跑 `prepare_session`（打开网站/登录/保存）

不想让它自动准备：

```bash
python main.py auto 新建作品1 --no-prepare      # 完全不准备
python main.py auto 新建作品1 --prepare         # 强制先准备
```

程序化接口 `ai_auto_chapter(..., prepare=True, prepare_app=app)`
（阶段零；准备失败会**直接返回**，不会带着未登录状态硬跑）。

### 新增的公开函数（`src/login.py`）


## 八点九、★★ 批量跑章（指定第3~第10章，自动逐章一条龙）

用户需求（2026-10-03）：

> 「我现有小说有100章，能不能指定生成第3到第10章，他就自动替换
>   我的指令模板，自动切换左侧的章节」

### 做了什么

指定一个章节范围（如第 3 ~ 第 10 章），程序自动：

| 步骤 | 说明 |
|---|---|
| ① 确保章节存在 | 左栏没有「第N章」→ 自动点「新建章节」补建（标题自动递增） |
| ② 切到该章 | 按标题关键词「第N章」切过去 |
| ③ 渲染剧情 | 用「当前章」替换指令模板（见下方 `#@`） |
| ④ 一条龙 | 续写 → 采纳 → 审稿 → 替换 |
| ⑤ 下一章 | 循环，直到跑完整个范围 |

### ★ `#@` = 当前章占位符（关键）

指令模板里除了原来的 `#N`（绝对章号，`#3` 永远是第3章），
新增 **`#@`**（或 `{{当前章}}` / `{{本章}}` / `#当前章`）代表
**「当前正在生成的这一章」**，批量循环每跑一章就自动替换成该章细纲。

```python
# 模板写法：
"根据 #@ 的细纲，续写本章正文，保持爽文节奏。前文脉络参考 #1。"

# 批量跑第3章 →  #@ 替换成第3章细纲
# 批量跑第4章 →  #@ 替换成第4章细纲
# ...
```

## 九、怎么加新任务

1. 打开 `src/tasks/adapters.py`
2. 照抄格式加一个：

```python
@register_task("自动发布章节", threaded=True)
def auto_publish(app):
    from src import actions as A
    page = app.page
    A.click(page, ["text=我的作品"], label="我的作品")
    A.fill(page, ['input[placeholder*="标题"]'], "第一章")
    A.wait_text(page, "保存成功")
```

3. 重启界面，任务中心里就会出现新任务卡片

可用动作（`src/actions.py`）：

```python
A.click(page, ["text=按钮文字", "[class*=btn]"])   # 多选择器，命中即用
A.fill(page, ['input[placeholder*="账号"]'], "值")  # 逐字符随机延迟
A.wait_text(page, "成功")                          # 等文字
A.wait_url(page, "/books")                        # 等 URL 关键词
```

**不知道选择器写什么？** 跑 `main.py recon`，或浏览器 F12 → 右键元素 → Copy selector。

## 十一、常见问题

**Q：会不会被封号？**
已做基础规避：真实 UA、去 `webdriver` 标记、动作随机延迟、优先用真实 Edge。
但站点有腾讯滑块，**操作过快仍会触发验证**。建议保持默认延迟，别加并发。

**Q：星月写作要每天重来登录吗？**
不用。登录一次后会话存进 `artifacts/storage/state.json`，之后自动复用。

**Q：我明明登录了，但提示没记录到 cookie？**
点「**我已登录，立即保存**」—— 不依赖自动检测，你确认了就强制存。
还想搞清楚原因就跑 `python main.py diag`，会打印全部 cookie 和判定过程。

**Q：还有软件登录框（授权码）吗？**
没有了 —— 2026-10-04 按用户要求删除了登录界面，只留一个主操控界面。
现在只有星月写作站点这一套登录态，见本文第三节。

**Q：登录态存在哪？安全吗？**
`artifacts/storage/state.json`，是**明文 JSON**，里面是你的登录票据——
等同于你的账号权限，**别外传、别提交 git**。`.gitignore` 已排除 `artifacts/`。

**Q：跑失败了怎么查？**
- `artifacts/screenshots/` 失败截图
- `artifacts/traces/` 录像，拖到 https://trace.playwright.dev 回放
- `artifacts/logs/` 完整日志
- 界面底部日志区也会实时显示

**Q：界面为什么用 tkinter 而不是网页？**
零额外依赖、启动快、可直接打包成 exe。用 Canvas 自绘实现了圆角、渐变等现代质感。

**Q：网站改版了？**
改 `src/config.py` 里的选择器，或在任务里多加候选选择器。业务代码不用动。
